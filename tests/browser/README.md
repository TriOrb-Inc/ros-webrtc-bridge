# Real Chromium connection tests

The Docker connection runner calls `verifyBrowserConnection({url, credential, iceServers?, relayOnly?, timeoutMs?})` from `connection.ts`. The URL uses HTTPS, credentials are injected at runtime, and `timeoutMs` defaults to 120 seconds. This shared deadline covers browser startup, context/page creation, health checks, and the entire scenario. Only the test context allows certificate errors when connecting to an isolated Gateway with a self-signed certificate. Credentials, SDP, ICE connection details, and payloads are not recorded in logs or reports.

Before the scenario, `/health` is polled every 250 ms, bounded by the lesser of 15 seconds and the remaining overall deadline. Only Chromium `ERR_CONNECTION_REFUSED`, `ERR_CONNECTION_RESET`, and `ERR_ADDRESS_UNREACHABLE` are retried. Non-200 responses, missing responses, timeouts, unknown errors, TLS errors, and browser-exit exceptions fail immediately. Each navigation and final wait stay within the remaining time; a 200 after the deadline is not success. The communication scenario is not retried after health succeeds.

Successful reports include `health.attempts`, the first fixed failure classification `firstFailure` (`none` when no failure occurred), `elapsedMs`, and the applied `timeoutMs`. Health failures expose a fixed `reason` and the same diagnostics through exported `BrowserHealthError`; its message contains only classifications and numbers. Later scenario failures retain health diagnostics. Cleanup failures do not overwrite the primary failure and are additionally reported as `cleanupFailed`. URLs and original exceptions are not retained. [Unit tests](../unit/browser/connection.test.ts) inject the clock and waits into `waitBrowserHealth` to verify transient recovery, deadlines, HTTP errors, unknown errors, and combined primary/cleanup failures without real-time waits.

The caller starts the ROS adapter and maps the independent rclpy peer's `in/out/cmd_vel/observed` to `/input`, `/output`, `/command`, and `/observed`. String messages are echoed unchanged; Twist messages are returned on observed as JSON Strings containing all six fields. The command lease is 250 ms.

A real browser acts as offerer and creates the three fixed DataChannels. After ICE gathering, it sends an authenticated `POST /offer`, applies the answer, waits for open channels, sends hello, and starts raw wire operations. It does not rely on SDK input validation. Responses must arrive on control, while subscribed String/observed messages must arrive on reliable. The receive queue is bounded to 1000 entries; all waits use short polls and deadlines.

The first connection and two reconnections verify unique-marker String echoes, all Twist fields, and rejection of expired leases. Reconnection also checks rejection of publication with the actual previous epoch. Rejection tests observe normal commands before and after the rejected one through an independent ROS peer. After draining normal samples, they require no new observed message during a 400 ms window. Lease timestamps do not compare browser and Gateway clock origins.

Twist values embed a run-specific random nonce and sample number in exactly representable finite values and are not reused between direct and relay runs. Comparing all six fields does not depend on JSON key order. Rejected Twist fingerprints remain monitored by every `onmessage` after the 400 ms window, so an illegal sample arriving during a later positive control or settling period also fails. This does not guarantee rejection of indefinitely delayed DDS data after the connection ends.

The local candidate type is read from the selected candidate pair in `getStats()`; relay-only runs require `relay`. Reports contain the browser version, anonymous health diagnostics, connection times, candidate types, reconnection count, and passing checks. The Node runner prints status every four seconds and releases all PeerConnections and Chromium even after failure. Closing the owned BrowserServer is limited to three seconds; a stuck server triggers termination of its owned process group. A kill request alone is not considered completion: child exit must be confirmed within another three seconds, or the test fails.

This helper alone is not a record of successful measurement. The Docker connection runner records actual results together with ROS distro and TURN usage.
